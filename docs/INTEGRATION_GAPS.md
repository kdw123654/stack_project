# 현재 백엔드로 연결할 수 없는 부분

확인 기준: STACK_BE 커밋 `22005747d66c2cf2d11431c917bdcad3655c38db`.
아래는 일반 라이브러리 사용법 문서로 해결할 수 없는 서버 인터페이스 문제입니다.

## 자소서·포트폴리오의 최초 서버 저장과 내보내기

B의 `POST /api/v1/cover-letters`, `POST /api/v1/portfolios`는 기존 B 공고 ID로 빈 프로젝트만 만듭니다.
B 공고를 최초 저장하는 `save_posting`, 자소서 생성 답변을 넣는 `update_cl`, 포트폴리오 생성 슬라이드를 넣는 `update_pf`는 Python 내부 함수입니다.
외부에서 호출할 HTTP 경로가 없습니다. 기존 답변/슬라이드 PATCH는 이미 존재하는 항목만 수정하므로 최초 생성 결과를 넣는 우회 경로로 사용할 수 없습니다.

B에 인증된 사용자 소유의 공고·프로젝트를 생성하고 A 생성 결과를 검증·저장하는 HTTP API가 필요합니다. A 임시 공고 ID와 B DB 공고 ID의 매핑도 필요합니다.
그 후 기존 `POST /api/v1/portfolios/{id}/export`로 파일 출력을 연결할 수 있습니다.
현재 프론트는 계정별 기기 저장과 다시 열기를 제공하며 서버 저장으로 표시하지 않습니다.

## URL 공고 수집

A `POST /job-postings/analyze`는 본문 text만 받습니다. B에 crawler.py는 있지만 URL을 받아 수집 결과를 반환하는 라우터는 없습니다.
현재는 공고 본문을 직접 입력합니다. URL 수집용 HTTP API를 B에서 노출해야 링크 입력을 연결할 수 있습니다.

## 슬라이드 하나 재생성·이미지 교체

A `POST /portfolios/generate`는 근거 경험이 연결된 6/10/14장 전체 구성안만 받습니다. 슬라이드 한 장만 만드는 API는 없습니다.
현재 전체 구성·생성 호출은 구현되어 있으며, 단일 재생성·이미지 교체 UI는 미지원으로 안내합니다.
단일 슬라이드 재생성 API 또는 전체 생성 비용을 명시한 별도 동작이 필요합니다.
이미지 교체는 전용 API 부재만의 문제가 아닙니다. 반환된 imageIds와 실제 이미지 URL을 매핑하고 선택하는 프론트 UI도 아직 구현하지 않았습니다.

## 운영 환경

A는 현재 인증 없는 로컬 개발용입니다. 브라우저에서 B와 A를 각각 호출하도록 연결했으며, 서비스 운영 전에는 B에서 소유권을 확인하는 A 라우팅이 필요합니다.
A 분석 결과·이미지는 만료되는 작업 캐시입니다. 영구 이미지 저장과 보관 정책은 B 저장소와 추가 연결해야 합니다.
실제 서버 주소·CORS/리버스 프록시·서버 환경 변수 설정과 실제 동작 확인은 별도입니다.

API가 존재하나 아직 프론트에서 사용하지 않는 항목과 검증 범위는 [재점검 문서](INTEGRATION_AUDIT.md)에 별도로 정리했습니다.
